================================================================================
MOTIVATION
================================================================================
Battery thermal behavior follows well-defined physical laws. However, the
observed temperature evolution varies significantly depending on operating
conditions such as:
  - Applied current I(t)
  - Cooling conditions (fluid temperature, mass flow)
  - Initial temperature T_0

Each experiment therefore produces a different outcome, even though the
underlying physics remains unchanged.

  KEY INSIGHT: We do not change the physics, only its parameters.

================================================================================
GOVERNING EQUATION (simplified 1D heat equation with internal heat generation)
================================================================================

  rho * c_p * dT/dt = k * d²T/dx² + Q_dot(t)

or equivalently (with thermal diffusivity alpha = k / (rho * c_p)):

  dT/dt = alpha * d²T/dx² + Q_dot(t) / (rho * c_p)

Physical meaning:
  - T(x,t)   : temperature field
  - k        : thermal conductivity
  - rho      : density
  - c_p      : heat capacity
  - Q_dot(t) : internal heat generation

================================================================================
KEY INSIGHT: PARAMETER DEPENDENCE
================================================================================
The PDE structure is fixed. But some terms depend on operating conditions:

  Q_dot(t) = f(I(t), operating conditions)

For example:
  Q_dot(t) ≈ I(t)^2 * R

  => Same PDE, but different parameters for each simulation.

================================================================================
BOUNDARY AND INITIAL CONDITIONS
================================================================================
Analogous to the PDE: structure is fixed, parameters depend on the simulation
inputs (T_init, T_fluid, m_dot, etc.).

================================================================================
NEURAL NETWORK FORMULATION
================================================================================
The network must include all relevant physical inputs:

  T = f_theta(x, t, physical_inputs)

where physical_inputs = [I(t), T_in, m_dot, T_init, ...]

================================================================================
GLOBAL LOSS FUNCTION (one loss across all simulations)
================================================================================

  L_total = L_data + L_PDE + L_IC + L_BC

Data Loss:
  L_data = | T_pred - T_true |

PDE Loss (T ≡ T_pred; parameters like I(t) come from phys_input):
  L_PDE = | dT/dt - alpha * d²T/dx² - Q_dot(I(t)) / (rho * c_p) |²

IC/BC Loss:
  Analogous — structure fixed, parameters from simulation inputs.

  KEY PRINCIPLE: The loss function is fixed, but its parameters depend on
  the simulation inputs.

================================================================================
INTERPRETATION
================================================================================
Each experiment corresponds to a different set of physical inputs:

  (x, t, inputs) --> T(x, t)

The network learns: how the solution changes when the physical conditions change.

  FINAL INSIGHT: One Equation + One Loss + Variable Inputs => Many Physical Scenarios

================================================================================
1) Modellfrage: Ein gemeinsames PINN fuer alle OPs oder getrennte Modelle?
================================================================================
Antwort: Ein gemeinsames PINN mit physikalischen Inputs (I, Tin, m_dot, T_init).
Die OPs unterscheiden sich nur durch diese Parameterwerte, nicht durch die Physik.

================================================================================
2) Modellfrage: Wie markiert man Datenpunkte fuer die richtigen Loss-Terme?
================================================================================
Antwort: Jeden Punkt mit op_id und point_type (data/pde/ic/bc) labeln.

================================================================================
3) Modellfrage: Wie kommen OP-spezifische Groessen in PDE, IC und BC?
================================================================================
Antwort: phys_input (I, Tin, m_dot, T_init) wird in alle Residuen eingesetzt:
  Q_dot(t) aus I(t), IC aus T_init, BC-Parameter aus Tin und m_dot.

================================================================================
4) Modellfrage: Wie wird Zeit in der PINN gelernt?
================================================================================
Antwort: Zeit als normalisierten Input (t oder tau=[0,1]) plus Data-Loss und
PDE-Zeitableitung dT/dt als Residual-Loss.

================================================================================
5) Modellfrage: Wie verhindert man, dass eine OP das Training dominiert?
================================================================================
Antwort: OP-balanciertes Batch-Sampling und adaptive Loss-Gewichte verwenden.

================================================================================
6) Modellfrage: Wie verbindet man phys_input mit dem Netzwerk?
================================================================================
Kontext: Sollen phys_inputs (I, Tin, m_dot, T_init) direkt mit allen Schichten
verbunden sein, oder nur als "Platzhalter" (d.h. die Gewichte werden auf 0
gesetzt, sodass sie keinen Einfluss auf die naechste Schicht haben)?

Idee (Pruning-Alternative):
  - NICHT manuell Gewichte auf 0 setzen (Pruning = Neuron fuer naechste Schicht
    deaktivieren, indem die entsprechende Spalte der Gewichtsmatrix auf 0 gesetzt wird).
  - Stattdessen: Standard-MLP verwenden und das Netz selbst die Gewichte lernen
    lassen. Wenn ein physikalischer Input irrelevant ist, wird das Netz seine
    Gewichte gegen 0 treiben.
  - Vorteil: Das Netz entscheidet datengetrieben, welche phys_inputs wichtig sind,
    anstatt dass wir es haendisch vorgeben.

================================================================================
KURZSCHEMA FUER MEHRERE OPs (praktisch)
================================================================================
- Netz-Input pro Punkt: [x, y, z, t, I, Tin, m_dot, T_init, SOC0].
- Marker pro Punkt: op_id (welche OP) und point_type (data/pde/ic/bc).
- Ort und Zeit: x,y,z,t immer als direkte Eingaben; t vorher normalisieren.
- Physik: PDE nicht als Input, sondern als Residual-Loss auf denselben Punkten erzwingen.
- OP-spezifisch: Q_dot(t) aus I(t), IC und BC je nach phys_input in PDE/IC/BC-Loss.
- Training: pro Batch alle OPs gemischt, aber balanciert sampeln.

Warum physikalische Groessen als Netz-Input sinnvoll sind:
- Fuer neue Szenarien aendern sich I, Tin, m_dot, T_init; ohne diese Inputs kann
  das Netz den neuen Fall nicht unterscheiden.
- Mit diesen Inputs lernt das Netz eine konditionierte Loesungsfamilie statt nur
  einzelne OP-Kurven.
- Bei der Auswertung eines neuen Falls setzt man nur neue Parameterwerte und
  bekommt direkt eine passende Vorhersage.
- Wichtig: Die PDE bleibt als Physik-Zwang im Loss; als Input kommen nur
  Szenario-Parameter, nicht die PDE selbst.
