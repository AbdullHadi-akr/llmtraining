# Battery Surrogate Workflow Data README

This file is the human-readable map for the workflow package.
Read this first when you want to know where each file lives, what it does, and which functions matter without reading the code.

## One-Sentence Summary

The workflow turns raw OP folders into cached model bundles for battery surrogate training, and this folder keeps the data rules, loader rules, cache rules, and smoke-test notes in one place.

## Main Rules

- `Inputsignale.csv` is the source of truth for OP setup.
- If the same profile exists as both `.csv` and `.xlsx`, the `.csv` file wins.
- OP08 is the known exception where the fluid-inlet profile is xlsx-only.
- OP19 uses module-test data and derived values, so it is not a simple scalar-only case.
- `soc_start` may be derived from OCV instead of being stored as a number.
- Any schema change should force a cache rebuild.

## What The Package Code Does

The Python package under `src/battery_surrogate/` is split into small modules so the reader can understand each job separately.

### `schema/columns.py`

This module stores the canonical names used everywhere else.

- `CANONICAL_CHANNELS` lists the seven OP setup channels.
- `BATEMO_FMU1_KEEP_COLUMNS` says which raw FMU1 columns are kept.
- `INPUTSIGNALE_COLUMN_ALIASES` maps raw header drift to canonical names.
- `COORDINATE_FILES` and `T_GRID_LAYER_COLUMNS` describe the three thermal layers.

### `schema/inputsignale.py`

This module turns `Inputsignale.csv` cell text into either a number or a known sentinel.

- `InputSentinel` names the special values like file-table, temperature-profile, and derive-from-OCV.
- `parse_inputsignale_value(raw, channel)` checks one cell and returns either `float` or `InputSentinel`.

### `schema/mapping.py`

This module connects raw OP folders to the right companion files.

- `resolve_profile_source(op_dir, channel)` finds the profile file for a channel.
- `load_op_matrix(path)` reads the OP matrix YAML file.
- `get_op_record(op_matrix, op_id)` returns one OP entry from that mapping.
- `serialise_op_matrix(op_matrix)` returns a stable JSON view for hashing and validation.

## Data Transformation Modules

### `data/filter.py`

Signal filtering and clipping for voltage and temperature.

- `clip_voltage(data, limits)` clips battery voltage to a safe range.
- `clip_temperature(data, limits)` clips grid temperatures to exclude unrealistic readings.

### `data/time_axes.py`

Time-axis validation and conversion.

- `as_float32_axis(times)` converts time values to float32 and ensures strictly increasing order.
- `is_strictly_increasing(times)` checks that a time axis has no duplicates or reversals.

### `data/paths.py`

This module knows where the workflow root and the important files are.

- `project_root()` returns the package root folder.
- `data_raw_dir()` and `data_cache_dir()` point to the working data folders.
- `coordinates_dir()` finds the thermal coordinate files.
- `load_yaml()` and `deep_merge()` help read config files safely.

### `data/errors.py`

This module defines the shared errors used by readers and builders.

- `MissingOpError` means an OP folder or OP record is missing.
- `MissingCoordinatesError` means one of the coordinate files is missing or malformed.
- `InsufficientDiskError` means the ingest or build step would run out of disk space.
- `SchemaChangelogError` means the schema version was not recorded correctly.
- `UnknownInputsignaleValueError` means a raw `Inputsignale.csv` value could not be understood.

## Core Data Flow

0. `cli/build_op_matrix.py` scans `data_raw/` and generates `op_matrix.yaml` from `Inputsignale.csv` values (run: `python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.build_op_matrix --force`).
1. `cli/ingest_raw.py` copies raw OP folders into `data_raw/` and writes `ingest_manifest.json`.
2. `data/raw_readers.py` reads the source CSV/XLSX files into clean arrays and tables.
3. `data/grid.py` reads the three coordinate tables and fixes the sensor order.
4. `data/assemble.py` combines raw inputs into one frozen OP bundle.
5. `data/cache.py` writes the bundle to disk and computes the cache key.
6. `data/loader.py` checks whether the on-disk bundle is current and loads it.
7. `cli/build_cache.py` drives the build for one or more OPs.

## Reader Functions In Plain Words

- `read_batemo_fmu1(path, encoding)` keeps the useful FMU1 columns and renames them to short canonical names.
- `read_heat_source(path, encoding)` reads the heat-source time series and keeps the source columns.
- `read_t_grid(path, layer, encoding)` reads one thermal layer and gives each sensor a stable column name.
- `read_fluidstoffwerte(path, encoding)` reads the single-row fluid property table and returns a `1 x 3` array.
- `read_inputsignale(path, encoding)` reads the OP setup row and returns a dictionary of numbers and sentinels.
- `read_time_series_input(path, channel, encoding)` reads one profile file and returns its time axis plus values.
- `read_module_test_data(path, encoding)` reads OP19 module-test data and returns one time series per channel.

## OpBundle Contract

The `OpBundle` dataclass is the frozen interface between the data pipeline and downstream models. Every field, shape, dtype, unit, and metadata key is documented in:

**[`docs/opbundle_contract.md`](docs/opbundle_contract.md)** — authoritative reference with source-of-truth hierarchy.

Key fields: `t_fast`, `t_slow` (time axes); `bc_V`, `bc_OCV`, `bc_I`, `pe_P_loss` (BCs); `T`, `q_source` (thermal); `xyz`, `layer`, `sensor_id` (grid); `sim_config_scalar`, `sim_config_ts` (parameters); `meta` (provenance).

## CLI Usage

Every module under `src/battery_surrogate/cli/` is a runnable command. Run with `--help` for details.

**This list must match `src/battery_surrogate/cli/*.py`; do not list commands that do not exist.**

### build_op_matrix.py

Generate or refresh `op_matrix.yaml` from raw data.

```bash
# Dry-run (print to stdout)
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.build_op_matrix --dry-run

# Generate and write (with safety check against overwrite)
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.build_op_matrix --force

# Validate drift (exit 0 if in sync, 1 if drifted, 2 on error)
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.build_op_matrix --check
```

### build_cache.py

Build cached model-ready bundles for one or more OPs.

```bash
# Build for all OPs in op_matrix.yaml
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.build_cache

# Build for specific OPs
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.build_cache OP01 OP02
```

### inspect_op.py

Print a short summary for one OP bundle (loads from cache).

```bash
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.inspect_op OP01
```

### ingest_raw.py

Copy raw OP folders from source into `data_raw/` and write `ingest_manifest.json`.

```bash
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.ingest_raw
```

### size_audit.py

Audit disk usage of raw data and cache folders.

```bash
python -m battery_surrogate_agenticWorkflow.src.battery_surrogate.cli.size_audit
```

## Builder Functions In Plain Words

- `assemble_op(op_id, ...)` reads all raw inputs for one OP and turns them into one `OpBundle`.
- `compute_cache_key(op_id, ...)` hashes the raw files, coordinates, build settings, and OP matrix slice.
- `save_bundle(...)` writes the bundle in the chosen storage format.
- `load_op(op_id)` checks the cache state and reloads or rebuilds if needed.
- `list_ops(regime)` reports which OPs are available, missing, stale, or out of date.

## Important Edge Cases

- OP08: fluid inlet profile is xlsx-only.
- OP10 to OP13: current profile files exist.
- OP15: more than one profile file type is present.
- OP19: module-test data, derived `soc_start`, a label-style `c_rate`, and explicit fallback provenance for missing ModuleTestData columns all matter.
- Any thermal grid file with the wrong row count should fail fast.

## Smoke-Test Order

1. Check that `raw_paths.local.yaml` points to the real source folder on this machine.
2. Check that the raw OP folders exist under `data_raw/`.
3. Check that the three coordinate CSVs are visible.
4. Build and load OP01 first.
5. Build and load OP08, OP10, OP12, and OP19 next.
6. Only then widen the run to the full OP set.

## Short Version For The Next Agent

If you only read a few lines, remember this:

- source data goes in `data_raw/`,
- cached outputs go in `data_cache/`,
- coordinates go in `coordinates/`,
- machine-local paths go in `configs/data/raw_paths.local.yaml`,
- and `Inputsignale.csv` plus the OP matrix drive the whole build.
